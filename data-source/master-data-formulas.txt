MASTER DATA FORMULAS
Companion reference for characters.json / weapons.json / artifact-sets.json / stat-types.json.
Everything here + those 4 files reproduces the full per-level/per-refinement game data (HP/ATK/DEF
at every level, talent values at every level, passive text at every refinement).


===============================================================================
1. LEVEL & ASCENSION RANGES
===============================================================================

Levels run 1-90, 95, 100. Ascension phases run 0-6. Every level has exactly one valid phase EXCEPT
the 6 breakpoint levels themselves -- 20, 40, 50, 60, 70, 80 -- which are valid at two
phases each: the one just reached and the one before it (same level, different stats).

Phase level cap (highest level reachable at that phase):
  phase 0: 20
  phase 1: 40
  phase 2: 50
  phase 3: 60
  phase 4: 70
  phase 5: 80
  phase 6: 90


===============================================================================
2. CHARACTER STATS -- HP / ATK / DEF + the ascension-unlocked bonus stat
===============================================================================

scalingRarity(name, rarity) = name starts with "Traveler" ? 4 : rarity
  (use scalingRarity everywhere below, never the raw `rarity` field directly; the 14 Traveler rows are
  named "Traveler (<Female|Male>) (<Element>)", e.g. "Traveler (Male) (Anemo)", so the prefix test
  still matches them -- see EXCEPTIONS below)

mainStat(base, maxAscension, scalingRarity, level, ascensionPhase, stat) =
  base * levelMultiplier(scalingRarity, level, stat) + maxAscension * ASCENSION_MULTIPLIER[ascensionPhase]

bonusStat(statName, scalingRarity, ascensionPhase) =
  bonusBase(statName, scalingRarity) * BONUS_ASCENSION_MULTIPLIER[ascensionPhase]
  (0 if statName has no entry below, or the entry for this rarity is null)

levelMultiplier(scalingRarity, level, stat):
  if level == 95 or level == 100:
    return LEVEL_95_100_MULTIPLIER[level][stat=="attack" ? (scalingRarity>=5?"fiveStarAtk":"fourStarAtk") : (scalingRarity>=5?"fiveStarHpDef":"fourStarHpDef")]
  base = (100 + 9 * level) / 109
  if scalingRarity >= 5: return round(base * (1900 + level) / 1901, 3 decimals)
  else: return round(base, 3 decimals)

ASCENSION_MULTIPLIER = [0, 38/182, 65/182, 101/182, 128/182, 155/182, 182/182]

EXCEPTIONS:
  - Traveler rows (since 2026-10-07): 14 separate characters named "Traveler (<Female|Male>) (<Element>)",
    one per protagonist x element (Anemo, Cryo, Dendro, Electro, Geo, Hydro, Pyro); Female = Lumine,
    Male = Aether. All 14 share the same stats (baseHp/baseAttack/baseDefense, maxAscension*, ascension
    stat ATK%, rarity, weaponType Sword) and exclusivityGroup "traveler". Per element: element, talents,
    constellations. A Male row differs from its Female row only in iconUrl (UI_AvatarIcon_PlayerBoy vs
    UI_AvatarIcon_PlayerGirl) and in the NormalAttack "Charged Attack DMG (Part 2)" baseValue
    (Male 0.60716, Female 0.7224; both Physical1). Talent levels and constellations are tracked per
    element in-game, while level, ascension, weapon and artifacts are shared by the protagonist.
  - Traveler (all 14 rows): stored rarity is 5, but stat GROWTH uses scalingRarity 4.
  - Traveler permanent story buff (all 14 rows; added 2026-10-07): after a story quest the Traveler
    permanently gains +50 base HP, +10 base ATK and +15 base Elemental Mastery (flat, NOT on the
    level curve: never add them to baseHp/baseAttack, which are multiplied by the curve). Handled in
    the app, NOT stored in characters.json; the official stat tables (Lunaris, HoYoWiki) and the
    formulas above exclude it. Values as stated by Eugene (not verified against a game source).
  - Lauma / Nefer: characters.json field `baseElementalMastery` is 200 / 100 (every other
    character is 0). This is a flat EM floor from level 1, OUTSIDE this formula entirely, and
    ADDITIVE with bonusStat() above when the character's own ascensionStat IS Elemental Mastery
    (true for Lauma). Total EM = baseElementalMastery + bonusStat("Elemental Mastery", ...).


===============================================================================
3. WEAPON STATS -- ATK + the secondary stat
===============================================================================

attack(attackTier, rarity, level, ascensionPhase, attackCurveRarity = rarity) =
  WEAPON_ATTACK_TIER_BASE[attackCurveRarity][attackTier] * WEAPON_ATTACK_LEVEL_MULTIPLIER[attackCurveRarity][attackTier - 1][level - 1]
  + WEAPON_ASCENSION_VALUE_BY_RARITY[rarity][ascensionPhase]
  (baseAttack isn't a stored field -- it's exactly WEAPON_ATTACK_TIER_BASE[attackCurveRarity][attackTier],
  confirmed to hold for all seeded weapons; storing it too would just be redundant)

secondaryStat(baseSecondaryStatValue, level) =
  baseSecondaryStatValue * secondaryStatMultiplier(level)

secondaryStatMultiplier(level):
  bucketStart = level < 5 ? 1 : floor(level / 5) * 5
  return WEAPON_SECONDARY_MULTIPLIER_CONTROL_POINTS value at that bucketStart
  (stepped, not interpolated -- levels 1-4 use level 1's value, 5-9 use level 5's, etc.)

===============================================================================
4. TALENT ATTRIBUTES -- per-level combat talent numbers (levels 1-15)
===============================================================================

value(curveType, baseValue, linearSlope, capLevel, customValues, level):
  index = level - 1
  if curveType == "Constant": return baseValue
  if curveType == "Custom": return customValues[min(index, len(customValues)-1)]
  if curveType == "Linear":
    effectiveIndex = capLevel != null ? min(index, capLevel - 1) : index
    return baseValue * (1 + linearSlope * effectiveIndex)
  else (one of the 9 named curves below):
    ratio = TALENT_CURVES[curveType][min(index, 14)]
    return round(baseValue * ratio, 6 decimals)
    (round BEFORE formatting -- the game stores each level's value rounded like this, and
    values that land exactly on a display boundary, e.g. 0.8085 -> 80.85% -> "80.9%", depend on it)

    section 9 (decided 2026-10-02; Albedo 5-Hit DMG Lv5 and Itto Low/High Plunge DMG (2) Lv9,
    previously Custom, were reverted to their curves and moved there).
    Preferred fix (2026-10-09): adjust baseValue so that every level displays the game's value (checked
    against the game's stored per-level values); section 9 lists only cells that can't be fixed that way.

FORMAT CODES (TalentAttribute.formatCode -- based on genshin-db's display convention
(node_modules/genshin-db/src/helper.js's formatTalentLabels), except I, which we round):
  I    integer -- value rounded half-up to a whole number, no scaling (e.g. 770.3755 -> "770",
       930.89 -> "931"); values that are already whole numbers (energy costs, counts) are unchanged.
       Needed for EffectFlat rows, whose stored values have decimals but display as integers.
       No thousands separator (e.g. "1695", not "1,695").
  P    percent -- value * 100, "%" suffix, no fixed decimal count (e.g. 0.6 -> "60%")
  F1   fixed, 1 decimal place, no "%" (e.g. 8.5 -> "8.5")
  F2   fixed, 2 decimal places, no "%"
  F1P  value * 100, 1 decimal place, "%" suffix (e.g. 0.904 -> "90.4%")
  F2P  value * 100, 2 decimal places, "%" suffix (e.g. 0.9047 -> "90.47%")

5. WEAPON REFINEMENT PASSIVE TEXT
===============================================================================

slotValue(curveType, baseValue, slope, customValues, refinement):
  if curveType == "Custom": return customValues[min(refinement - 1, len(customValues) - 1)]
  else (Linear): return baseValue + slope * (refinement - 1)

format(value) = round to 4 decimal places, then drop trailing zeros (e.g. 24 not 24.0000)

render(template, slots, refinement):
  replace each "{n}" in template with format(slotValue(slots[n], refinement))
  (a number that never changes across refinements has NO slot at all -- it's already
  plain text in the template)

EXCEPTIONS:
  - Exaiphanes Blade: weapons.json field `passiveDescriptionTemplate` is null -- use
    `refinementEffects` instead (5 raw rows, already the final text, no rendering needed).
    Its passive gains an entire extra clause starting at R2 that R1 doesn't have at all.
  - 14 weapons have small pure copy-editing differences between refinement tiers that don't
    touch any number (e.g. "an opponent" vs "an enemy", a missing "the"). The template's
    wording always reflects the LAST known refinement, not the first -- rendering at earlier
    refinements will legitimately read slightly differently than genshin-db's original
    per-refinement text did, but every number still matches exactly. Affected weapons:
    A Thousand Floating Dreams, Ash-Graven Drinking Horn, Blackcliff Slasher, Bloodtainted
    Greatsword, Dragonspine Spear, Frostbearer, Halberd, Lost Prayer to the Sacred Winds,
    Mistsplitter Reforged, Nocturne's Curtain Call, Otherworldly Story, Sequence of Solitude,
    Skyward Blade (R2 only: the game text has a stray comma, "5%, Gains"; R1/R3/R4/R5 read "5%. Gains"),
    Snow-Tombed Starsilver.


===============================================================================
6. WEAPON STAT BONUSES -- unconditional passive bonuses shown on the stat screen
===============================================================================

One row per (weapon, statType) in weapons.json's `statBonuses`, using the SAME
curveType/baseValue/slope/customValues shape as section 5's slots (Constant/Linear/Custom
instead of just Linear/Custom -- see below for why):

statBonusValue(curveType, baseValue, slope, customValues, refinement):
  if curveType == "Constant": return baseValue
  if curveType == "Custom": return customValues[min(refinement - 1, len(customValues) - 1)]
  else (Linear): return baseValue + slope * (refinement - 1)

Most weapons have zero rows here (most passives are conditional/proc-based, not an
unconditional stat-screen bonus). Checked all 72 currently-seeded rows (42 weapons, 2026-10-09): all are Linear, 0
Constant, 0 Custom -- but unlike section 5's slots, "Constant" IS a real stored case here,
not "no row at all": a stat bonus is a queryable fact regardless of whether it scales, whereas
a constant passive-TEXT number just becomes literal text with nothing to store. This is also
why this can't simply reference a section-5 slot instead of duplicating a small amount of data
-- every currently-seeded stat bonus's value happens to also exist as a slot on the same
weapon (checked directly), but a future Constant stat bonus would have no slot to reference at
all, so each row stands on its own instead of pointing at one.

What counts (Eugene 2026-10-09): only a boost that always applies to the wearer's own stats. Conditional
effects (after/when/while/stacks), boosts to the whole party or tied to a specific character (Traveler, Aloy),
stat conversions ("ATK increased by X% of Max HP") and attack-specific bonuses (Elemental Skill CRIT Rate, Charged
Attack DMG, ATK SPD) get no row. An all-element DMG Bonus ("12% All Elemental DMG Bonus") is stored as 7 rows, one
per element DMG Bonus% (Pyro, Hydro, Electro, Cryo, Anemo, Geo, Dendro), like Tiny Miracle's RES rows.
